# 사용자 맥락과 그에 따른 설계 제약

이 문서는 나머지 설계 문서보다 우선한다.
차트 규칙·지표 구성·검색 UX에서 판단이 갈릴 때 여기 적힌 것을 기준으로 정한다.

---

## 1. 실사용자

주 사용자는 개발자 본인이 아니라 **개발자의 할아버지**다.

| 항목 | 내용 |
|---|---|
| 투자 경력 | **30년 이상. 전문가** |
| 지표 이해도 | ROE·PER·PBR 등은 당연히 알고 계심 |
| 기기 | **PC / 노트북** |
| 접속 | 가족 전용 URL (북마크로 진입) |
| 이 프로젝트의 계기 | ChatGPT에 "기업 영업이익 비교 그래프"를 요청했다가 거절당함 |

**고령 + 전문가**라는 조합이 핵심이다. 둘을 헷갈리면 설계가 어긋난다.

- 고령이라고 **이해력**을 낮잡으면 안 된다 → 지표를 감추거나 쉬운 말로 바꾸지 않는다
- 전문가라고 **가독성**을 소홀히 하면 안 된다 → 글자·선·대비는 넉넉하게

## 2. 이 맥락이 바꾸는 설계 결정

### 2.1 지표 노출 — 감추지 않는다

❌ ~~쉬운 지표만 기본 노출하고 ROE·PER은 "더보기"에 넣는다~~
✅ 13개 지표를 **카테고리별로 정리해서 전부 평면 노출**한다 (절대값 / 비율 / 밸류에이션)

기본 선택값만 영업이익·영업이익률로 둔다. 이건 이해도 문제가 아니라
**빈 화면으로 시작하지 않기 위한 진입점**이다.

### 2.2 툴팁 — 개념 설명이 아니라 계산 근거

전문가에게 "ROE란 자기자본이익률로…"는 소음이다. 필요한 건 **이 숫자가 어떻게 나왔는가**다.

```
❌ "ROE: 자기자본 대비 얼마나 이익을 냈는지 보여주는 지표입니다"
✅ "ROE = 지배주주순이익 / 평균 지배주주지분
    K-IFRS 연결 기준 · 기초자본 결측으로 기말자본 사용"
```

### 2.3 데이터 정합성 표시 — 이게 신뢰의 조건

30년 하신 분은 영업이익 숫자가 이상하면 **바로 알아채신다.**
숫자가 틀리면 서비스를 안 쓰시고, 근거를 못 밝히면 못 믿으신다.
따라서 아래를 화면에서 확인 가능하게 만든다:

| 표시할 것 | 이유 |
|---|---|
| **연결 / 별도** 배지 | 섞이면 숫자가 완전히 달라진다. CFS 폴백 시 명시 |
| **지배주주 기준** 명시 | ROE·EPS가 지배주주순이익 기준임을 밝힌다 |
| **결산월** 배지 | NVDA 1월 결산이 2021 자리에 찍힌 이유 |
| **실제 회계기간** 병기 | 툴팁에 `NVDA FY2022 (2021.02–2022.01)` |
| **주식수 기준 시점** | 유통주식수(자기주식 제외)임을, 어느 분기 값인지 |
| **데이터 출처** | DART / SEC, 조회 시점 |
| **"데이터 없음"** 구분 | 0과 결측을 절대 같게 보이게 하지 않는다 |

파생지표를 저장하지 않고 조회 시점에 BASE 값으로 계산하는 설계
(`02-architecture.md` 3장)가 여기에 직접 기여한다. 근거를 항상 되짚을 수 있다.

### 2.4 검색 — 한글 별칭이 필수

SEC `company_tickers.json` 에는 영문명만 있다:

```json
{"cik_str":1045810,"ticker":"NVDA","title":"NVIDIA CORP"}
```

**"엔비디아"로 검색해도 안 나온다.** 전문성과 무관한 문제다.

필요한 것:
1. 미국 주요 기업 **한글 별칭 테이블** (엔비디아, 인텔, 애플, 마이크론, 테슬라 …)
   - 최소한 시가총액 상위 + 국내 투자자 관심 종목 200~300개
   - `company_aliases(company_id, alias, alias_type)` 테이블로 관리
2. **초성 검색** — `ㅅㅅㅈㅈ` → 삼성전자
3. 티커·종목코드 직접 입력도 그대로 지원 (전문가는 `005930`을 아신다)
4. 오타 허용은 후순위 — 정확 매칭 + 전방 일치 + 초성으로 충분

### 2.5 가독성 — 시력 기준으로 잡는다

| 항목 | 기준 |
|---|---|
| 본문 기본 폰트 | **16px 이상**, 차트 축 라벨 14px 이상 |
| 차트 선 굵기 | **2.5px 이상** (Recharts 기본 1px은 너무 얇다) |
| 명도 대비 | WCAG AA (4.5:1) 이상. 기업별 색상 팔레트도 이 기준으로 고른다 |
| 색상 구분 | 색맹 안전 팔레트. 색만으로 구분되지 않게 **선 스타일도 함께** 달리한다 |
| 클릭 타깃 | 최소 40×40px |
| 숫자 표기 | 조/억 단위 축약 + 천단위 구분 (`4.5조`, `391,035백만$`) |

### 2.6 PC 확정 — 호버 동기화 그대로 간다

기기가 PC/노트북으로 확정되어 원래 기획한 **호버 동기화가 그대로 유효**하다.
터치 대응 재설계는 필요 없다. (다만 차트 스택은 `overflow-x` 없이 반응형으로 두어
브라우저 창을 줄여도 깨지지 않게 한다)

### 2.7 첫 화면

빈 검색창만 두지 않는다. 바로 누를 수 있는 프리셋 비교를 배치한다:

```
삼성전자 · SK하이닉스 · 마이크론    (반도체)
삼성전자 · Intel · NVIDIA          (원래 기획 시나리오)
현대차 · 기아 · Tesla              (자동차)
```

## 3. Phase 순서 변경

원래 계획에서 **주가 연동(PER/PBR)을 뒤로 미룬다.**

| 원래 | 변경 |
|---|---|
| Phase 4 = 주가 연동 및 PER/PBR | Phase 4 = 다중 지표·정규화·내보내기·URL 공유 |
| Phase 5 = 다중 지표, 정규화, 내보내기 | Phase 5 = 주가 연동 및 PER/PBR |

**이유 두 가지:**

1. 할아버지가 실제로 요청하신 건 **영업이익 비교 그래프**다. PER이 아니다.
2. 미국 주가 API 무료 티어는 셋 다 약관에서 공개 이용을 금지한다
   (`00-data-sources.md` 3.4). 반면 DART·SEC는 배포 제약이 없다.
   **라이선스가 깨끗한 구간을 먼저 끝내 실사용을 시작**하는 편이 낫다.

즉 Phase 3까지만 끝나도 "삼성전자 vs Intel vs NVIDIA 영업이익률 10년 추이"가
동작한다. 그 시점에 할아버지께 드리고 피드백을 받는다.
